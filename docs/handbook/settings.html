Settings

Global blocking behavior, DNS rebinding protection and DoH3

The Settings tab contains global options that affect how blockasaurus responds to blocked queries.

The Settings page

Block Type

Controls how blockasaurus responds when a query matches a blocked domain.

OptionResponseBehavior
Zero IP 0.0.0.0 (A) / :: (AAAA) Returns a null IP address. The client’s connection attempt fails immediately. This is the most compatible option and works well with browsers and apps.
NXDOMAIN NXDOMAIN (name does not exist) Returns a standard “domain does not exist” DNS error. Some applications handle this more gracefully; others may show confusing error messages.
REFUSED REFUSED (server refuses to answer) Returns REFUSED for every query type, with no answer or authority records. Stub resolvers and forwarders commonly treat REFUSED as a server failure and fall back to another configured DNS server, which bypasses blocking — so use it only where blockasaurus is the client’s sole resolver.
Custom IP The address(es) you name A comma-separated list of destination addresses, e.g. 192.0.2.10, 2001:db8::1. Include one IPv4 and one IPv6 address to cover both A and AAAA queries. Useful when a web server on that address serves a “blocked” page. Set it through the API; the dropdown shows a stored custom value but does not offer one.
✓

Zero IP is recommended for most setups. It’s the default and causes the least confusion for end users — blocked pages simply fail to load rather than showing DNS error messages.

Block TTL

The Time-to-Live for blocked domain responses. This controls how long the client (and any intermediate caches) remembers that a domain was blocked before querying again.

Format is a duration string: 1m (one minute), 30s, 1h. The default is 1m.

It applies to the block types that return records — Zero IP, NXDOMAIN and a custom IP. REFUSED returns no records at all, so Block TTL has no effect there.

ValueTrade-off
0s Client re-queries every time. Most responsive to unblocking changes, but more load.
1m (default) Good balance. Unblock takes effect within a minute.
1h Reduces query load significantly. Changes take up to an hour to propagate.

DNS Rebinding Protection

In a DNS rebinding attack, a site you visit resolves its own domain to an address on your local network, so the page in your browser can reach your router, your NAS, or anything else behind the firewall — from the outside, wearing an origin your browser trusts. Turning on Enable rebinding protection makes blockasaurus drop any answer from the upstream resolvers that points at a private, loopback, link-local or unspecified address.

Answers from Custom DNS, the hosts file and conditional upstreams are never inspected, so internal zones you serve yourself keep working with no extra configuration.

Allowed Domains

Some names legitimately resolve to a private address through the public upstreams — a NAS, a router admin page, or any split-horizon record whose public DNS entry points into your LAN. Add those here. Each entry also matches its subdomains, so example.com covers nas.example.com.

Entries must be plain domain names. Wildcards (*.example.com), regexes and whitespace are rejected — subdomain matching is automatic, so a wildcard would not buy anything.

⚠

A missing entry fails quietly. The name does not error — it resolves to nothing, for every client at once, and the only trace is a REBIND row in the query log. Before turning this on, list the internal names that resolve to a private address in public DNS and add them first.

DNS over HTTP/3 (DoH3)

blockasaurus serves DNS-over-HTTPS on the HTTPS port over TCP. Turning on Serve DoH over HTTP/3 adds a second transport for the same endpoint: HTTP/3 over QUIC, on the UDP counterparts of that port. The win for DNS is mostly in connection setup — QUIC folds the transport and TLS handshakes together, and a returning client can resume at 0-RTT. QUIC also recovers from loss per-stream, so on a lossy link concurrent queries no longer wait behind each other's retransmits; a single query still waits for its own.

There is nothing to configure on the client. The DoH URL does not change, and HTTPS responses carry an Alt-Svc header advertising HTTP/3, so clients that support it switch transports on their own and the rest keep using TCP. The line under the toggle tells you whether this server is serving over HTTP/3 right now, and the Setup Guide on each client group says so in its introduction.

⚠

This setting needs a restart — it is the only one on this page that does. Apply rebuilds the resolver chain, which is enough for blocking, custom DNS and upstreams, but it cannot open or close a network listener. After saving, the page tells you the change is stored and not yet in effect; restart blockasaurus to pick it up.

HTTP/3 needs somewhere to bind, so it requires an HTTPS port to be configured, and it cannot be used together with PROXY protocol on that port — QUIC carries no PROXY protocol header, so client IPs would stop matching those seen over TCP. When either applies, the toggle says so instead of claiming a restart would help; both are YAML-only settings (ports.https and ports.proxyProtocol).

Applying Settings

Each section saves independently — Save Settings for blocking behavior, Save Rebinding Settings for rebinding protection, Save DoH3 Setting for HTTP/3. Then click Apply in the header to put changes into effect. Blocking behavior and rebinding protection need no restart; DoH3 does, and Apply does not help it.
